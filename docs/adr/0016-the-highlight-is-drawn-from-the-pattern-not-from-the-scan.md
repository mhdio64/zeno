# The highlight is drawn from the pattern, not from the scan

A search produces two different answers, and it is tempting to have the background scan produce both. The scan already knows every match in the document, so the renderer could be handed their positions and paint them. Instead the pattern is compiled once and the renderer matches it against the visible lines itself, while the background scan is left to do what only a background scan can do: count the matches in the whole file and find the next one.

The reason is that the two answers have different lifetimes. A scan works on a snapshot: it is started against a document as it was, and its result is thrown away if the document changes underneath it — that is the rule the spec already set for every background result. The highlight has to be right *now*: for the text on screen at this instant, including edits that were never saved and lines that were never in the file. A result that arrives late is a result about a document that no longer exists. Re-matching the visible lines against the pattern costs one regex pass over one screen of text, which is bounded by the width of the terminal, and it is always about the present.

The consequence is that the count and the highlight can disagree for a moment, and they will. The count is a whole-file number that arrives when the scan finishes; the highlight is instant. That is the right way round — a number that is right is worth more than a number that is immediate — and the status line says "counting…" until the count is known, so the user is never shown a number that is not one.

A second decision rides along: the pattern is compiled as it is typed, not when the search is submitted. A pattern that does not compile is reported on the prompt line, where the user can see what they typed, and the last pattern that did compile keeps its highlight — so the viewport does not go blank while a typo is being fixed. The pattern is compiled on every keystroke, which is cheap: the regex crate compiles a short pattern in microseconds, and only the visible lines are ever matched.
